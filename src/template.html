Why a string?

One name, one color, everywhere

Basing it on a name means less to think about: no colors to pick and nothing to sync. The same name gives the same hex values on every machine, and the palette below works in any editor.

  1. Open the project folder in VS Code, then run Preferences: Open Workspace Settings (JSON) from the Command Palette. This opens .vscode/settings.json and creates it if it doesn't exist.
    2. 
          
  2. Paste the snippet inside the existing outer braces, or tick the braces option for an empty file. In a .code-workspace file, paste it inside the "settings" object.
    3. 
          
  3. Save. The colors apply to this project's window only.
    4. 
        

        
The dark colors apply to any theme with “Dark” in its name, and the light colors to any theme with “Light” in its name. With any other theme you get only the title bar, activity bar and status bar.

        
The syntax and editor colors layer on top of your base theme. Anything the base theme styles with a more specific scope than the ones listed can still show its own color, so Default Dark Modern and Default Light Modern give the most predictable result.

        
This snippet colors only the parts you ticked, each with its own text colors, so it works over any theme you already use. It does not change your base theme.

Color-blind separation

        
Each row shows the six syntax colors and plain text as that viewer would see them, plus the two that sit closest together. Distance is measured in OKLab; around 0.05 and above is easy to tell apart, and below 0.03 is tight. Syntax colors also differ in brightness, and comments are italic.

        

      

    

  


  

    
Colors are designed in OKLCH, then gamut-mapped to sRGB hex, the only format VS Code theme colors accept. Wide-gamut and HDR colors cannot be expressed in a theme.

    
Contrast uses the WCAG 2 ratio on the final hex values. Targets: 7:1 for body text, 4.5:1 for other text, 3:1 for controls and indicators.
